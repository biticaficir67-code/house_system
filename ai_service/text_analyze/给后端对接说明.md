# 房源文案智能分析 —— 给后端的对接说明

这份说明只写后端需要知道的部分。算法在 Python 里已经写好，Java **不用重写分词和模型**，只要在房源保存、查询时把结果接上。

房价预测如果也走 `ai_service`，请各写各的子目录。文案分析在：

`house_system/ai_service/text_analyze/`

端口固定 **5001**，避免和别人可能用的 5000 冲突。

---

## 1. 这块在干什么

用户录入房源时会填三段文字：**核心卖点、小区介绍、周边配套**。

Python 服务会：

1. 先把错别字、表情、打分之类整理成正常说法（例如「经装修」当成精装修，「打十分」当成口碑较好）
2. 用已经训练好的 TF-IDF / LDA（以及没有模型时的 TextRank）抽出和卖点有关的词
3. 给出页面上能直接展示的 **卖点标签、需注意、一句话小结、词云用词**

前端详情页会有一个「智能分析」区域，数据来自你们库里存的这些字段，**不要把接口返回的整段 JSON 直接铺在页面上**。

---

## 2. 需要后端做什么

请在 **房源新增 / 修改保存成功之后** 调一次本接口，把返回结果写进数据库，和该条房源绑在一起。

详情、列表（如果列表要展示几个标签）时 **不要每次再调 Python**，直接读库即可。文案改过才需要再调一次、覆盖旧结果。

建议流程：

1. 本机先启动 Python 服务（见第 6 节）
2. Spring Boot 用 `RestTemplate`（或你们项目里现成的 HTTP 工具）POST 到 5001
3. `code == 0` 时把 `data` 拆开入库
4. Python 没启动或超时：房源本身仍应保存成功，分析字段留空即可，不要整单回滚

区域位置可以传，当前识别不按具体城市、区划处理，传了也不影响。

---

## 3. 接口在哪个文件、地址是什么

| 说明 | 位置 |
| --- | --- |
| HTTP 入口 | `house_system/ai_service/text_analyze/app.py` |
| 识别逻辑 | `house_system/ai_service/text_analyze/house_nlp.py` |
| 离线训练（后端不用调） | `house_system/ai_service/text_analyze/train.py` |
| 训练好的模型 | `house_system/ai_service/text_analyze/data/text_model.joblib` |

对外只用下面两个 POST，**处理函数是同一个**，任选一个即可，建议统一用 `/ai/analyze`。

- `POST http://127.0.0.1:5001/ai/analyze`
- `POST http://127.0.0.1:5001/ai/extract-tags`

探活（可选，页面不用）：

- `GET http://127.0.0.1:5001/ai/health`

`Content-Type: application/json`。也兼容表单，优先 JSON。

## 4. 请求体

中文键或英文键都可以，有哪个用哪个。

```json
{
  "核心卖点": "满五唯一，近地铁，精装修",
  "小区介绍": "人车分流，物业服务比较好",
  "周边配套": "出门就是商场和医院，公交站在门口",
  "区域位置": ""
}
```

对应英文键：`coreSelling`、`communityIntro`、`surrounding`、`district`。

三段文案来自房源表里你们已经约定要加的字段。空字符串可以传，不要传 `null` 导致拼接出 `"null"`。

---

## 5. 返回体（请按字段入库）

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "summary": "该房源突出近地铁、精装修……",
    "advantages": ["近地铁", "精装修", "有电梯"],
    "disadvantages": ["有抵押"],
    "wordFreq": [
      { "name": "地铁", "value": 12.3 },
      { "name": "精装修", "value": 8.1 }
    ],
    "keywords": [],
    "topic": {},
    "method": "训练模型 TF-IDF + TextRank"
  }
}
```

`code` 非 0 或请求失败：不当成分析成功。

**建议入库、给前端用的：**

| 字段 | 含义 | 建议存法 |
| --- | --- | --- |
| `summary` | 一句话小结 | `VARCHAR` / `TEXT` |
| `advantages` | 卖点标签列表 | JSON 字符串，或逗号分隔 |
| `disadvantages` | 文案里写到的问题、以及同类主题里本文没写到的对照 | 同上 |
| `wordFreq` | 词云用的词和权重 | JSON 字符串（数组） |

**可以忽略、不要展示给用户的：**

- `keywords`：和 `wordFreq` 相同，存一份即可
- `topic`：LDA 主题，给算法自己看的
- `method`：用了哪种抽取方法，页面不用写出来

`advantages` 举例：近地铁、公交便利、近医院、近学校、近商圈、商业配套、近菜市场、近公园、精装修、拎包入住、采光好、有电梯、人车分流、满五唯一、口碑较好 等。

## 6. 后端怎么启动依赖、怎么调

依赖在 `text_analyze/requirements.txt`。本机一次：

```text
pip install flask jieba scikit-learn joblib
```

每次开发或演示前，在 `text_analyze` 目录启动：

```text
python app.py
```

看到 `Running on http://127.0.0.1:5001` 就不要关这个窗口。Spring Boot 再启动。

Java 调用示例（思路即可，按你们项目包名改）：

```java
RestTemplate restTemplate = new RestTemplate();
Map<String, String> body = new HashMap<String, String>();
body.put("核心卖点", house.getCoreSelling());
body.put("小区介绍", house.getCommunityIntro());
body.put("周边配套", house.getSurrounding());
String url = "http://127.0.0.1:5001/ai/analyze";
// 设置 Header 为 application/json，POST 后读取 code、data
```

超时建议 3～5 秒。连不上时记下日志，房源照常保存。

---

## 7. 希望在后端、在系统里是什么样

- 房源表（或单独一张分析表，用房源 id 关联）能查到该套房的小结、卖点、需注意、词云数据
- 录入/修改是「触发分析」的时机；分析失败不影响房源落库
- 给前端的接口只返回上面建议入库的字段，不要把 `topic`、`method` 原样丢到页面
- 本模块 **不计算房价、不打性价比分数**，那些如果要做是另一块服务
- 词云、标签展示由前端做；后端负责存和读

对接时有字段对不上，优先改 Java 的 JSON 键名，尽量不要改 Python 里已经定好的 `data` 结构。
