# 业务导入、图片与客户匹配更新

更新日期：2026-10-26。沿用现有 `backend/src/main/java/system` 模块结构。前端保留原来的导航、客户列表、修改/删除流程和房源列表地图布局，新增能力通过原页按钮和弹窗补充；本轮没有修改队员数据库 SQL、Python 服务和 `ReportCustomController.java`。

## 1. 业务 Excel / CSV 导入

入口：原有房源、客户、业主管理页中，点击新增按钮旁的“表格导入”，在弹窗内完成操作。没有新增顶级导航或独立工作台页面。旧 `/import` 地址兼容转到原管理页的导入弹窗。

1. 在房源、客户或业主管理页点击“表格导入”；导入类型随当前页面固定。管理员明确选择门店和负责人；经纪人固定为本人及所属门店。
2. 下载 Excel 或 CSV 模板，按标题填写。Excel 的第二张表提供逐列说明；第一张表只放业务数据。
3. 选择文件，点击“校验并预览”，核对原表行号、错误、重复和补充资料提醒。可以下载校验结果。
4. 点击“确认导入”写入有效新记录。错误行与明确重复行跳过，不覆盖原记录；有其他写入错误时，本批有效行整体回滚。

限制和规则：

- 支持 `.xlsx`、`.xls` 和 UTF-8 / GB18030 CSV；每个文件最多5MB、每批1000条。Excel 只读第一张表，公式须粘贴为值。
- 同时支持中文模板标题和 camelCase / snake_case 字段名。多选值支持逗号分隔或文字 JSON 数组。日期支持 `2026-10-26`、`2026/10/26`、不补零的月日以及 Excel 日期单元格。
- 金额以列标题为准：模板为元，房源另兼容“挂牌价(万元)”；两种挂牌价不能同时填写。不要直接把万元数填到元列。
- 房源必填：小区、区域、建筑面积、总楼层；城市默认杭州，其他缺少的户型、价格等资料提示后续补齐。
- 客户、业主必填姓名和电话；电话建议设为文本，防止 Excel 吞掉前导0。客户模板可同时填写预算、面积、区域、室数等需求。
- 房源按可见范围内来源编号去重；未提供编号时，按标准化后的整行内容生成编号，因此不能把它当作模糊房源合并。客户、业主按同店可见范围的电话和姓名判断；同一电话出现不同姓名须人工核对。
- 文件里的归属列不控制权限，服务端以所选且有权操作的门店和经纪人为准。
- 预览凭证绑定当前账号、类型与归属，15分钟失效；服务重启后需要重新预览。单账号最多4个未完成预览，全局最多24个缓存批次。
- 同一预览成功确认后再次确认，在凭证有效期内返回同一结果；确认时还会再次查重和检查负责人。并发导入通过事务锁串行处理，不宣称替代人工录入的全局唯一约束。
- 导入房源为下架、待核验，来源标记为 IMPORT。不会一次触发大量 AI 请求，可在详情按需分析。
- 这是业务数据导入，不支持执行 SQL，不自动还原或替换数据库。

现有 `database/全量清洗房源_v1.csv` 的编码、字段名、朝向数组和日期格式已纳入解析兼容；不代表文件每行都符合业务校验，实际结果以预览为准。

## 2. 图片上传与上架检查

进入“房源管理 → 详情 → 房源图片”：

- 可批量选择 JPG / PNG / WebP，显示上传进度和逐文件失败原因；每张不超过50MB，每套房源最多20张图片。
- 支持图片预览、设封面、排序和移除。已有视频仍可查看；本轮新增入口只选择图片。
- 图片读取使用登录请求头，地址不拼接登录凭证。服务端验证文件签名、大小、数量及房源权限。
- 图片调整后房源下架并变为待核验，页面同步最新版本和上架检查清单。已成交房源只读。
- 上架前检查小区、区域、有效面积和户型、正数挂牌价、图片、核验结果、门店与经纪人状态。合法的0厅、0卫可保留。

正常流程：录入或导入房源 → 补全资料和图片 → 管理员核验 → 经纪人/管理员上架。清单用于说明缺项，最终写入仍由后端校验。

图片文件位于本机配置 `app.upload.directory`，数据库只保存关联信息。给队员同步代码时，已有本地图片不会自动变成对方的文件；需一起部署上传目录或后续接统一文件存储。

## 3. 客户画像、房源推荐与差异

入口：保留原客户列表，在原修改、删除按钮旁补充“需求与匹配”；详细功能在弹窗内使用。

- 维护标签、购房预算、面积、室数、意向区域、装修、预计购房日期和沟通说明。页面预算使用万元，提交时按十进制换算为元。
- 只对已填写的结构化条件计算符合度；说明文字不自动推断条件。“有电梯”标签作为明确电梯偏好，其余标签仅分类。
- 需求为空时提示先保存需求，不返回虚构的100分推荐。未保存的编辑会提示推荐仍依据已保存需求。
- “完全符合条件”要求所有已填条件符合且资料已知；“包含可协商方案”展示差距或未知资料，不隐藏超预算问题。
- 只选同店、当前权限内、已核验的在售房源，同时排除门店或负责经纪人无效的记录。管理员也不推荐无法直接预约的跨店房源。
- 预算、面积、区域、室数、装修和电梯按启用条件归一化权重。均衡、预算优先、面积优先采用不同权重；同分时预算优先按价格升序，面积优先按面积降序。
- 数字条件超出范围时，按差值相对边界的25%逐步扣分，最低0；未知资料不得视为符合。未完全符合时分值最高99。
- 每套返回符合项、差异、缺失项、预算超额、挂牌单价和详细评分依据。这个分值是规则符合度，不是成交概率或模型预测。
- 支持最多三套横向比较，以及带入房源、客户和经纪人的预约入口；预约仍需选择未来时间并确认。差异方案先提醒核对。
- 同一工作区可以保存跟进记录、下次联系时间；管理员可填写原因交接客户负责人。
- 最多分析5000套候选、返回100套；页面取前50套，大范围截断会明确提示。

## 4. 本轮修正

| 问题 | 处理 |
| --- | --- |
| 房源普通编辑清空未展示字段 | 前端回传原资料；后端对未提交的可选字段保留原值，显式 null 仍可清空可空字段 |
| 0厅/0卫保存后丢失 | 使用空值判断，保留数字0 |
| 地图小区名被当作HTML解析 | 两处地图提示改为 DOM textContent |
| 前端和后端重复触发文案分析 | 页面不再重复发送保存后的分析请求 |
| 上传图片后版本不一致 | 每次操作后刷新房源和上架检查；冲突提示刷新 |
| 注册后无法查审核或被拒后重提 | 新增独立申请会话、查询、审核意见和重新申请入口；与业务登录凭证隔离 |
| 审核默认误分第一家门店 | 通过时显式选店，已有门店保留原店，审核意见必填 |
| 开通账号使用固定共享密码 | 改为逐个填写登录名和初始密码 |
| 客户资料更新误清空标签 | 未传 tags 时保留原标签，显式空数组可清空 |
| 旧集成检查底稿缺原表账号 | 同步现有 H2 schema 的 sys_admin、broker、sys_oper_log 和无 sys_user 外键的会话表；管理员初始化从门店接口取门店 |

“表格导入”弹窗提供只读数据质量提醒，包括未来完成/成交日期、缺挂牌日期和缺图片。不会自动改写队员历史数据。

## 5. 接口补充

均以 `/api` 开头，业务鉴权和统一响应保持原约定。模板接口直接返回文件。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /imports/catalog | 支持类型、字段和文件限制 |
| GET | /imports/{kind}/template?format=xlsx或csv | 下载模板，kind为HOUSE/CUSTOMER/OWNER |
| POST | /imports/{kind}/preview | multipart：file、storeId、brokerId；返回previewToken、各类计数和rows |
| POST | /imports/{kind}/commit | JSON：previewToken；返回导入、重复、错误计数与新增记录编号 |
| GET | /imports/quality | 仅管理员，全局数据质量计数 |
| GET | /houses/{id}/readiness | checks、completionPercent、missing、canPublish、version |
| GET | /customers/{id}/recommendations | mode=STRICT/FLEXIBLE，priority=BALANCED/BUDGET/SPACE，limit=1～100 |

原 `/customers/{id}/matches` 继续返回严格匹配数组。`PUT /customers/{id}/demand` 可附客户最新version；新版页面会传入，旧调用方可继续使用。保存需求后客户版本递增。

图片沿用现有接口：POST `/houses/{id}/media`；GET `/{mediaId}/content`；PUT `/{mediaId}/cover`、`/order`（均带房源version）；DELETE `/{mediaId}`。内容接口同样需要 Bearer Token。

## 6. 当前验证范围和边界

本轮执行后端编译/打包、前端生产构建和本机页面查看；没有执行自动测试套件。运行时确认三类Excel模板均正常生成，上架检查和空需求推荐正常返回；取组员CSV前三行做只读预览，得到1条有效、2条重复、0条错误，未确认导入。构建通过不能代替完整业务写入回归，导入确认、上传、封面、核验、预约等写入流程仍需在专用联调数据上走完。

保留队员报表原控制器、数据库底稿和 Python 代码。Python 交付检查的 Windows 临时目录占用问题未在本轮处理。历史样例日期、缺图片及字段缺项仍按真实数据提示。前端已有图表大包提示属于后续性能优化项。

本机环境仍使用原来的 `http://127.0.0.1:5174/`。本机 MySQL 和运行依赖仍位于 `backend/target`，不要执行 clean 或清空该目录。`start-local.cmd` / `start-local.py` 依赖本机已有任务和环境，仅供当前电脑使用，不随本次功能提交共享；组员按后端 README 配置和启动自己的环境。
